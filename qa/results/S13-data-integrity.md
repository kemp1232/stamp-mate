# S13-data-integrity — Results

Covers schema constraints, FK `onDelete` behavior, cascades, and unique constraints in `prisma/schema.prisma` and the raw migration SQL. Executed directly against the local Supabase Postgres DB (`postgresql://postgres:postgres@127.0.0.1:56322/postgres`) via the `pg` pool in the harness (no `psql` binary available in this environment, so all queries went through `S13-data-integrity/s13.js`, run with `node S13-data-integrity/s13.js` from `<SCRATCH>/qa`). All rows created were scoped to freshly-generated, `uid()`-suffixed test tenants — never touching another agent's data. Destructive cascade cases (S13-003, S13-013, S13-014) were run inside `BEGIN … ROLLBACK` so the mutations were observed in-transaction and then undone, verified by re-querying the real (non-transactional) DB state afterward.
